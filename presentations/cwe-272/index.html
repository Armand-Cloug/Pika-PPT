POURQUOI CETTE FAILLE EST GRAVE ?

MODIFICATION DE FICHIERS

Elle permet la modification de fichiers sensibles.

ACCÈS À DES RESSOURCES

Elle permet d’accéder à des ressources réservées.

ACCÈS POUR UN HACKER

Si le programme est compromis, le hacker hérite de tous ses privilèges.

UN PRINCIPE FONDAMENTAL DE LA CYBER

LE PRINCIPE DE MOINDRE PRIVILÈGE

OÙ TROUVE-T-ON CETTE FAILLE ?

  • SCRIPT

    Exécution d’un script Python ou Bash en tant que root, par exemple.

  • PROGRAMME

    Un programme en C qui manipule des fichiers sensibles, par exemple.

  • APPLICATION

    Une application web sans restriction, par exemple.

  • CRON

    Tâches planifiées avec des droits supérieurs à ceux nécessaires.

QUELS SONT LES RISQUES ?

Élévation de privilèges

Exécution de code arbitraire

Modification ou suppression de données sensibles

Compromission du système d’information

CAS TECHNIQUES CONCRETS

Voici différents exemples de cas techniques concrets menant à la CWE 272.

  1. 1

    Un serveur web lance une commande en sudo, mais le système ne redescend pas ses droits ensuite.

  2. 2

    chroot isole un programme dans un dossier, mais sans chdir le programme n’est pas restreint à ce dossier.

  3. 3

    Utiliser une bibliothèque externe (Python, par exemple) qui utilise des droits élevés sans vérification.

SE PROTÉGER DE CETTE FAILLE

  • Ne jamais exécuter de programme avec plus de droits que requis

  • Retirer les droits après usage

  • Utiliser des environnements restreints

  • Toujours vérifier les tâches exécutées automatiquement

  • Auditer régulièrement les configurations

SEVEN PERNICIOUS KINGDOMSA TAXONOMY OF SOFTWARE SECURITY ERRORS

QUI ?

Katrina Tsipenyuk et Brian Chess (Fortify Software), Gary McGraw (Cigital). Publié par le NIST.

POUR QUI ?

Les développeurs et les experts en cybersécurité.

QUAND ?

Cet article a été publié en 2005.

POURQUOI ?

Créer une classification des erreurs de sécurité, à la racine : dans le code source.

LA TAXONOMIE 1 / 2

INPUT VALIDATION

Entrées non filtrées, injection, XSS

API ABUSE

Mauvais usage des fonctions et API

SECURITY FEATURES

Authentification, mots de passe, cryptographie

TIME & STATE

Problèmes de synchronisation

LA TAXONOMIE 2 / 2

ERRORS

Mauvaise gestion des erreurs

CODE QUALITY

Qualité du code, mémoire, obsolescence

ENCAPSULATION

Fuites de données, mauvaise isolation

ENVIRONMENT

Erreurs de configuration de l’environnement

LA PARTIE SYSTÈME

  • SECURITY FEATURES

    Gestion des privilèges, des mots de passe ou des accès

  • TIME & STATE

    Système décalé, hors du temps

  • API ABUSE

    Appels système mal utilisés (chroot)

  • ENVIRONMENT

    Mot de passe en dur ou mode debug activé
